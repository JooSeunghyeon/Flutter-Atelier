# late final 초기화식 실패·재진입·순환과 재시도 정책 캐시 비교

Dart `late final` 필드(초기화식 있는 형태)와 최상위/정적 `final` 지연 초기화의 실패·재진입·순환 동작을 실행으로 검증하고, 실패 시 재시도 정책을 명시적으로 가진 캐시 설계와 비교한다.

## 검증하는 질문

1. **초기화 실패 후 재시도**: `late final int v = flaky();`에서 초기화식이 첫 접근 때 예외를 던지면 필드는 미초기화로 남고, 다음 접근에서 초기화식이 다시 실행되어 성공 값이 저장되는가? 이후 접근은 초기화식을 다시 실행하지 않는가?
2. **재진입**: 초기화식 안에서 같은 필드를 다시 읽으면(재진입) `LateInitializationError`가 발생하는가?
3. **순환 참조**: `late final int self = self + 1;` 또는 a↔b 상호 참조 순환은 `StackOverflowError`가 발생하는가?
4. **최상위 final 재시도**: 최상위 `final top = (){...}();` 초기화식이 첫 접근에서 예외를 던지면 다음 접근에서 다시 실행되어 성공할 수 있는가?
5. **설계 비교**: 위 기본 동작과 대비해 (a) 실패를 기억해 같은 오류를 계속 돌려주는 캐시, (b) 실패 시 재시도 횟수를 제한하는 캐시의 호출 횟수는 어떻게 다른가?

각 시나리오는 초기화 함수 호출 횟수와 예외 타입을 비교하여 동작을 확인한다.

## 실행 방법

```bash
dart run src/main.dart
```

모든 검증이 통과하면 `ALL_CHECKS_PASSED`를 출력하고 exit code 0으로 종료한다.  
하나라도 실패하면 실패 내용을 출력하고 exit code 1로 종료한다.

테스트 파일 실행:

```bash
dart run test/late_final_initializer_test.dart
```

## 관찰 결과

### late final 초기화 실패 후 재시도
- 첫 접근에서 초기화식이 예외를 던지면 필드는 미초기화로 남는다
- 두 번째 접근에서 초기화식이 다시 실행되어 성공 값이 저장된다
- 세 번째 접근은 저장된 값을 반환하고 초기화식을 다시 실행하지 않는다
- 초기화 함수 호출 횟수: 2번 (첫 실패 + 두 번째 성공)

### late final 재진입
- 초기화식 안에서 같은 필드를 다시 읽으면 초기화식이 다시 실행된다 (재진입)
- 바깥 실행이 계속 진행되고, 안쪽 실행이 먼저 값을 저장하면 바깥 실행이 대입을 시도하는 시점에 `LateInitializationError: Field 'value' has been assigned during initialization.` 가 발생한다
- 초기화식 호출 횟수: 2번 (바깥 1번 + 안쪽 재진입 1번)
- 오류 발생 후 필드는 안쪽 실행이 저장한 값을 가진다

### late final 순환 참조
- `late final int self = self + 1;` 자기 참조는 `StackOverflowError`가 발생한다
- a↔b 상호 참조 순환도 `StackOverflowError`가 발생한다
- VM 스택이 고갈될 때까지 초기화식이 반복 실행된다
- 이 동작은 VM 구현에 의존한다

### 최상위 final 초기화 실패 후 재시도
- 최상위 `final top = (){...}();` 초기화식이 첫 접근에서 예외를 던지면 다음 접근에서 다시 실행된다
- late final 필드와 동일하게 실패 후 재시도가 가능하다
- 성공 후에는 초기화식이 다시 실행되지 않는다

### 실패 기억 캐시
- 초기화 함수가 첫 호출에서 예외를 던지면 그 예외를 저장한다
- 이후 접근은 초기화 함수를 다시 실행하지 않고 저장된 예외를 던진다
- 초기화 함수 호출 횟수: 1번 (첫 실패만)
- 캐시 get 호출 횟수: 여러 번 가능 (모두 같은 예외 반환)

### 재시도 한도 캐시
- 초기화 함수가 예외를 던지면 최대 시도 횟수(maxAttempts) 내에서 다시 실행한다
- 최대 시도 횟수 내에서 성공하면 그 값을 저장하고 이후 접근은 초기화 함수를 다시 실행하지 않는다
- 최대 시도 횟수를 초과하면 더 이상 초기화 함수를 실행하지 않고 "재시도 한도 초과" 예외를 던진다
- 초기화 함수 호출 횟수: 최대 maxAttempts만큼

### 호출 횟수 비교
- **late final**: 실패 후 재시도하여 성공 시 초기화 함수 2번 호출
- **실패 기억 캐시**: 실패 후 재시도하지 않아 초기화 함수 1번만 호출
- **재시도 한도 캐시**: 실패 후 재시도하여 성공 시 late final과 동일하게 2번 호출

## 헷갈리는 점

- **late final은 실패를 기억하지 않는다**: 첫 접근에서 예외가 발생해도 필드는 여전히 미초기화 상태이고, 다음 접근에서 초기화식이 다시 실행된다. 네트워크 호출이나 파일 읽기 같은 부작용이 있는 초기화식은 여러 번 실행될 수 있다.
- **재진입과 순환은 다르게 처리된다**: 재진입(같은 필드를 초기화 중에 읽기)은 읽기가 초기화식을 다시 실행시키고(총 2회), 안쪽 실행이 먼저 값을 저장한 뒤 바깥 실행이 대입을 시도하는 순간 LateInitializationError가 발생한다. 순환 참조(자기 자신이나 상호 참조)는 안쪽 실행이 끝나지 않아 StackOverflowError가 발생한다. 둘 다 같은 재진입 메커니즘이지만 안쪽 실행의 완료 여부에 따라 결과가 다르다.
- **StackOverflowError는 VM 동작이다**: 순환 참조 시 발생하는 StackOverflowError는 VM 스택 한도에 도달했을 때 발생하는 것으로, Dart 언어 스펙이 보장하는 동작이 아니다. 다른 Dart 구현(예: 웹)에서는 다를 수 있다.
- **실패 기억 캐시는 영구 실패를 가정한다**: 초기화가 실패하면 이후에도 계속 실패할 것이라고 가정하고 재시도하지 않는다. 이는 일시적 실패(네트워크 오류 등)에는 적합하지 않다.
- **재시도 한도 캐시는 일시적 실패를 허용한다**: 제한된 횟수만큼 재시도하여 일시적 실패를 복구할 기회를 주지만, 한도를 초과하면 더 이상 재시도하지 않는다.
- **late final 기본 동작은 무한 재시도**: late final은 성공할 때까지 매 접근마다 초기화식을 다시 실행한다. 초기화식이 항상 실패하면 매번 예외가 발생한다.
- **최상위 final도 동일한 재시도 정책**: 최상위 final 지연 초기화도 late final과 동일하게 실패 후 재시도한다.
